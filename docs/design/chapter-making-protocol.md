# Raccord 章节创作协议 · v1.0

> 本文件是可演化的制作协议，不是永久宪法。  
> 它适用于《Le ciel de Poincaré》之后的新候选章节，不追认第一章已经完成后来新增的全部步骤。

## 目标

先证明相遇成立，再制作视觉表面；先让第二章活起来，再为章节建书架。

章节不是固定模板。这里的步骤约束验证顺序，不规定每章必须有中心物体、主动操作、三幕结构或持久化状态。

## 状态

- **命题**：一句话矛盾，尚无实现；
- **候选**：有研究与机制方向，仍可整体推翻；
- **原型**：存在独立直达体验，但没有正式入口；
- **canon**：作者明确认可并进入作品；
- **实验档案**：曾承担核心探索，后来退出当前 canon。

工程完成度不能自动提升作品状态。

## 顺序

### A｜命题

写清：

1. 访问者无法置身事外的关系是什么；
2. 世界通过什么法则回应；
3. 去掉人物姓名与说明后，什么仍然成立；
4. 为什么静态海报、文章或视频不足以承载它。

答不出来时不画最终视觉。

### B｜真实性边界

当作品援引历史原文、数学结论、物理规律、工程事实或人物立场时，先核验来源与适用边界。

原创神话与作品语言不伪装成史实，也不需要为了显得深刻强行附会人物。

### C｜机制原型

先用最低成本证明关系：

- 不依赖最终 raster、昂贵材质或宏大场景；
- 与正式首页、Enter、既有章节和工具隔离；
- 失败后可以完整删除；
- 优先验证时间、约束、感知和后果，而不是动画完成度。

### D｜作者体验

作者亲自使用，不先读实现解释。

如果主要记忆仍是“拖了一个东西”“看了一个动画”“画面很漂亮”，原型不能因为 QA 通过而进入下一阶段。

### E｜不知情访客

用少量不知情访客验证核心关系，而不是让他们猜设计师的标准答案。

记录：

- 他们首先注意到什么；
- 他们自然做了什么；
- 他们离开后如何描述这次相遇；
- 哪些提示必须依赖说明文字；
- 哪些地方被误读成小游戏、模拟器或普通网页。

测试结果帮助作者判断，不以投票替代作者判断。

### F｜不同身体关系

桌面、移动、键盘、触摸与减弱动态分别证明同一核心关系。它们可以使用不同构图和手势，不机械压缩同一页面。

### G｜作品 QA

同时检查：

- 命题与视觉是否一致；
- 材料是否诚实；
- 世界法则是否可辨认；
- 事实与引用是否可核验；
- 时间与持久状态是否诚实；
- 性能、输入方式与语义是否不背叛核心关系；
- 新增内容替代或隐退了什么。

### H｜Canon 决定

只有作者明确认可后才：

- 建立正式入口；
- 更新章节索引与公开元数据；
- 把候选事实写入产品正本；
- 提交、推送、合并或部署。

具体 Git 与部署权限仍服从项目开发工作流。

## 当前应用

### Chapitre I · Le ciel de Poincaré

按 2026-07-23 当时口径获得轻量认可，作为既有 canon 保留。它的三界、seed / memory / scar 与三幕节奏属于第一章，不升级为协议模板。

### Chapitre II · L’horizon immobile

当前仍是候选原型。

可以保留：

- 观察者失去静止特权；
- 一次选择后失去控制；
- 世界在离开后继续；
- 返回时证据已经增加；
- 独立状态不污染 Poincaré。

已经被作者否定：

- 大铜球作为视觉与动作中心；
- 石厅表面承担“法国性”；
- 拖动球体作为主要记忆；
- 依靠背景偏转完成揭示。

下一步只在独立 `/horizon` 实验路径重做可见机制：让时间留下的证据成为主角。作者重新认可前，不改 Enter、Home、导航或 canon。
